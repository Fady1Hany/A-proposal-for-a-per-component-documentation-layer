## change_impact
<!-- [authored] -->

- Changing the signature of `authenticate(credentials)` requires updates to all three consumers (`LoginController`, `SessionManager`, `AuthMiddleware`). This is the primary entry point and is treated as a stable public interface — see `public_interface` below.
- Changing token validation logic (delegated to `TokenValidator`) may affect `SessionManager` session creation, since `SessionManager` calls `authenticate` indirectly through `AuthMiddleware`.
- Changes to error types thrown by `authenticate` propagate to `LoginController`, which maps them to HTTP status codes. New exception types must be added to `LoginController`'s exception handler.
- Changes to `UserRepository` interaction patterns do not affect consumers, since they only see the boolean return of `authenticate`.
